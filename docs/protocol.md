# Protocol v1

JSON over WebSocket. Every frame is an `Envelope` (`src/plural/protocol/envelope.py`):
`v, id, kind (cmd|evt|ack), type, room, ts, actor, seq, to, token, re, ok, error, payload`.

- Commands: `src/plural/protocol/commands.py` (discriminated by `type`).
- Events: `src/plural/protocol/events.py`; durable events carry `seq`, transient ones do not.
- Unknown fields are ignored, unknown `type` is rejected with `invalid`.
- JSON Schema for clients: `uv run python scripts/gen_schema.py` → `web/src/protocol/schema.json`.

Relay framing (`src/plural/protocol/relay.py`): host opens `/host/{room}` with `relay.open` (public key + signature over room id); guests connect to `/{room}`; relay wraps guest frames into `relay.frame{conn,data}` and reports `relay.closed`.

Prompt mode: `session.set_prompt_mode` (host only) appends `session.prompt_mode_changed`; `SessionState.prompt_mode` is `open` (participant prompts go straight to the agent) or `review` (they become proposals). See ADR 0004.

Permission mode: `session.set_permission_mode` (host only) appends `session.permission_mode_changed`; `SessionState.permission_mode` is `default` (edits and commands ask), `accept_edits` (writes are allowed), `plan` (writes and commands that are not allowed by a rule are denied, and each prompt carries a plan-mode note to the agent) or `auto` (writes and commands are allowed). Deny rules and the guest-turn taint apply in every mode. The host resets it to `default` on start.

Context: `SessionState.context` holds the agent's context fill (`tokens`, `window`, `compact_at`) and follows `context.usage`, which the host appends after every model response, after a compaction and when the model changes. `context.compact` (host only) starts a compaction at once when the agent is idle, as a run with an empty `prompt_id`; during a run it is deferred to the next step. A transient `context.compacting` (`run_id`, `tokens_before`) marks the start of every compaction, automatic or requested, and `context.compacted` its end.

MCP: `SessionState.mcp` lists the host's MCP servers (`name`, `transport` of `stdio` or `http`, `scope`, `status` of `connecting`, `ready`, `failed` or `off`, `tools`, `error`) and follows `mcp.changed`. The host-only commands `mcp.add` (`name`, a `command` with `args` or a `url`, `scope`), `mcp.toggle` (`name`, `enabled`), `mcp.restart`, `mcp.remove` and `mcp.import` change them; connecting happens in the background and shows up as later `mcp.changed` events. Server environment and headers never appear in events. MCP tools reach the agent as `mcp__<server>__<tool>` with risk `exec` and subject `<server>/<tool>`.

Models and sub-agents: `agent.changed` carries the main model's label in `agent` and the fast model's in `fast` (empty when there is none); `SessionState.fast_agent` follows it. `SessionState.agents` lists the sub-agents (`name`, `description`, `role` of `fast` or `main`, `tools`, `scope`, `read_only`) and follows `agents.changed`. The host-only `agents.create` (`name`, `description`, `prompt`, `tools`, `model`, `scope`) writes an agent file into `.agents/agents` and `agents.remove` deletes one Plural wrote. A sub-agent is the `agent` tool with risk `read` when all its tools read, `exec` otherwise; its own tool calls go through the host's gate and stream into the `agent` call's output.

Usage: at the end of every run the host appends `usage.recorded` with `lines` of `role`, `model`, `agent` (empty for the conversation, `compact` for summaries, or a sub-agent's name), `uses` and `usage`. `SessionState.usage` adds them up per role, model and agent.

Skills: `SessionState.skills` lists the installed skills (`name`, `description`, `scope` of `project` or `global`) and changes with `skills.changed`, which also names what was `added` and `removed`. `skills.search` (participants and the host) answers the sender alone with a transient `skills.found` holding `hits` of `package` (`owner/repo@skill`), `name` and `installs` from skills.sh. `skills.install` (host only, `scope` defaults to `project`) downloads the skill from GitHub in the background; a failure comes back to the sender as an `error` event. `skills.remove` (host only) deletes a skill from a folder Plural installs into.

Agent: `SessionState.agent` names the agent that answers (for example `anthropic · claude-opus-5-5`) and follows the durable `agent.changed` event. It changes only while no run is active.

Host control channel (not part of the wire protocol): a client that started its own host with `plural-host host --json` keeps the host's stdin open and writes one JSON object per line, `{"id", "type": "configure" | "test" | "catalog" | "install", "config": {"provider", "model", "base_url", "api_key", "context_window"}}`. The host answers on stdout with `{"type": "result", "id", "ok", ...}`: `configure` swaps the provider and returns the new `agent` label, `test` makes a short real request and returns `message` or `error`. `catalog` returns the provider presets (each with the optional SDK it needs, `extra`) and `extras`, the optional model SDKs (`anthropic`, `openai`) with whether each is installed. `install` takes `"extra": "anthropic" | "openai"` and installs that SDK into the host's own environment from the pins its package declares, so a client can offer it without restarting the host. Closing stdin stops the host. API keys travel only through this local pipe, never in protocol frames, argv or the log, and a key received here is added to the redactor at once. For `anthropic_oauth`, the host reads its own `anthropic-oauth.json` file; OAuth tokens do not enter control frames.

Live output: while `bash` runs, the host broadcasts the transient `tool.output` with whole lines (batched at most every 100 ms, at most 64 KB per call) after redaction; `tool.ended` still carries the complete output. Clients show the tail and must not rely on receiving every chunk.

Queue: a prompt accepted while a run is active is appended to `SessionState.queue` (`prompt.accepted` with an active run) and leaves it with `prompt.dequeued` and a reason: `delivered` when the agent takes it, `cancelled` when the author or the host removes it with `queue.cancel`, `dropped` when the run is aborted or the host restarts.

Joining: `session.hello` carries one of `token`, `invite` (one-time) or `join` (the permanent room link, the `?join=` of the link). With a valid `join` the host either admits the person at once (`link.set_admission` = `open`, kept in `SessionState.admission`, default `approve`) or keeps the connection open and sends the transient `session.pending` to it. Nothing else reaches a waiting connection. The host's clients get the durable `join.requested` (`request`: `id`, `name`, `client`, `requested_at`, also kept in `SessionState.join_requests`) and answer with `join.decide` (`allow`, `viewer` or `deny`, host only); `join.resolved` closes the request with a decision of `allow`, `viewer`, `deny`, `expired`, `gone` (the person left) or `revoked`. An allowed person receives `session.welcome` and the snapshot on the same connection, a refused one the transient `session.refused` with a reason, which clients treat as final. Requests, their resolutions and `SessionState.join_requests` are delivered to the host only. `invite.create` with `reusable` returns the room link, an `invite.created` with `reusable` set and no `expires_at`; `link.revoke` (host only) replaces the code, refuses everyone waiting and returns the new link. At most `max_pending_joins` people wait, each for `join_timeout_s`, and the room holds `max_participants` connected people. Someone who joins with a token or a one-time invite is never asked.

Writing: a viewer sends `access.request` (an optional `note` of up to 200 characters; anyone else gets a conflict). The host's clients get the durable `access.requested` (`request`: `participant_id`, `name`, `note`, `requested_at`, also kept in `SessionState.access_requests`, keyed by participant) and answer with `access.decide` (`participant_id`, `allow` or `deny`, host only). `access.resolved` closes the request with `granted` or `denied`; a grant is followed by `participant.role_changed` to `participant`, a removal or a role change by anyone drops a waiting request. The request and its answer go only to the host and to the person asking, and a snapshot carries a person only their own request. A person waits for 5 minutes after a refusal before asking again, only `max_pending_joins` requests wait at once, and one person has one request at a time. The host revokes the right with `participant.set_role` to `viewer`.

Briefings: a viewer or participant sends `briefing.request` (`focus` up to 300 characters, `update`), the host answers with `briefing.decide` (`allow` or `deny`) unless `SessionState.briefing_sharing` is `team` (granted at once) or `off` (a conflict); `session.set_briefing_sharing` (host only) sets it, default `ask`. `briefing.requested`, `briefing.resolved` (`granted` or `denied`) and `briefing.delivered` (`to`, `text`, `as_of_seq`, `update`, `error`) go only to the host and the asker, and a snapshot shows a person only their own request. A person waits a minute between requests and has one at a time. The asker hands the text to their own host with `briefing.import` (host only, `source`, optional `as_of_seq`, `text` up to 20,000 characters), which answers a repeated `source` and `as_of_seq` with a conflict and emits the public `briefing.imported`; the agent then reads the text as untrusted notes before its next prompt and every later run counts as guest-originated.

Team members: `session.hello` may carry `team` (`certificate`, `ts`, `nonce`, `proof`) instead of a token, an invite or the link. See ADR 0007.

Team chat: `chat.send` (host and participants) takes `text` (at most 2000 characters), `to` (a participant id for a private message, otherwise the whole room) and `mentions` (participant ids, at most 20, deduplicated by the host). The host appends the durable `chat.posted` event (`message_id`, `author_id`, `text`, `to`, `mentions`) and keeps the last 200 in `SessionState.chat`. A private message (`to` set) is delivered only to its author and its addressee: the host filters live events, `history.get`, the replay after `session.hello.since` and the chat in `session.snapshot.state` per connection, so sequence numbers seen by a client can have gaps. The recipient must exist, differ from the author and not be a viewer. Chat events never enter the agent's context: the conversation is rebuilt only from prompts, replies and tool calls (`host/history.py`).

Presence: `presence.typing` (host and participants) announces that the sender is composing a prompt. The host broadcasts the transient `participant.typing`, never stores it, repeats nothing while the state is unchanged, ends it when the prompt is accepted, the sender leaves or six seconds pass without a refresh, and lists who is typing in `session.snapshot.typing`.

Policy: `policy.add` / `policy.remove` (host only) append `policy.rule_added` / `policy.rule_removed` events; the live session rules are `SessionState.policy`, the built-in rules arrive in `session.welcome.base_policy`. `Always` and `Block` approval decisions are recorded as rules by the host.
